## What I bring to a team

- **Operational context:** translating reservation handling, guest correspondence
  and reception work into concrete requirements and acceptance criteria.
- **Application troubleshooting:** following a problem through the interface,
  API, database, import process and deployment configuration.
- **Verification discipline:** using targeted tests, reproducible builds and
  explicit evidence to review changes before accepting them.
- **Maintainable handovers:** setup instructions, documented failure cases and
  clear boundaries between a demonstration and a live system.

## Engineering beyond the interface

The interesting work is often invisible on a screenshot: distinguishing consent
from a required booking step, limiting retained data, rejecting unauthorised
operations, preventing duplicate imports and planning recovery after a failed
release. Read the [mechanisms and limitations](https://gitlab.com/maciejszulia/maciejszulia/-/blob/main/engineering-practices.md).

## How these projects were developed

I define requirements, prioritise work and coordinate implementation and verification
with AI coding tools, including Claude Code and Codex. These are AI-assisted projects;
I do not present the entire codebase as manually written by me. The case studies
separate my contribution, implemented mechanisms and checks actually performed.

**Conversation starters:** follow a reservation from the website to reception;
