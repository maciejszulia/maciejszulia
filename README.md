## Private systems in real use

**AgroCamping website and booking API.** A website in Polish, English and German with a separate booking API and reception integration. Shared booking rules, transactional capacity checks and idempotency handle repeated requests. A persistent outbox tracks notification attempts separately from booking acceptance. Payment callbacks are verified. Guests of a working accommodation business send booking requests through this website.

Next.js, React, TypeScript, Node.js, MySQL/MariaDB, Stripe, GitLab CI

[Technical overview](case-studies/agrocamping-website.md) | [Public website](https://www.agrocamping.eu/) | [The business on Google Maps](https://www.google.com/maps?cid=12963305277474159664)

**AgroCamping Reception.** An internal application that connects reservations and guest enquiries with reception work and financial records. Repeated imports preserve pitch and price changes made by reception staff. Receipts, refunds and reversals are reconciled as financial evidence, separately from booking status.

TypeScript, Astro, Express, Prisma, SQLite, Python, shell tooling, GitLab CI

[Technical overview](case-studies/agrocamping-reception.md)

## Small services around those systems

Each one is a separate process with one job.

Reception, runit services:

- **Panel backend, gateway and health probe**: three services; the probe checks the panel every 30 seconds.
- **Mail sync**: imports guest mail from Gmail into the panel and counts consecutive failures per step.
- **Arrival notifier**: sends a push notification about arrivals through ntfy.
- **Maintenance**: periodic database backup.
- **Watcher**: checks panel health, free disk space, the website API, backup age and certificate expiry; it notifies only when a state changes.
- **Certificate renewal**: a daily loop renews the TLS certificate of the panel.
- **Weather**: fetches weather data into a cache.

Website, GitLab CI and Docker:

- **Weekly security job**: dependency audit (npm audit, osv-scanner), secret scan (gitleaks), TLS check (testssl), HTTP header check (MDN Observatory) and link check (lychee).
- **Preview deployment**: a CI job deploys a static preview of the website to a local Kubernetes cluster (k3d).
- **Uptime monitoring**: Gatus in Docker with its own configuration and alerts.

Workstation:

- **Fan control**: a fan curve with hysteresis for the laptop.
- **Resource watchdog**: measures system resources and writes a report; it does not kill any process.
- **TLS front for a local SearXNG instance**: a small Node.js service.
- **Off-site backup**: encrypts the latest database backup with GPG (AES-256) and stores it outside the machine.

## How I work

I write the requirements, AI coding agents write the code, and I accept the result on tests.

- **Claude Code** (Anthropic): a coding agent in the terminal. It reads the repository, plans, writes and tests code, and runs subagents.
- **OMX, oh-my-codex**: orchestration on top of OpenAI's Codex CLI. Planning, teams of agents each in its own git worktree, quality gates at the end.
- **OMC, oh-my-claudecode**: multi-agent orchestration for Claude Code, run as a separate instance.
- **Hermes Agent** (Nous Research): an autonomous agent with memory, scheduled jobs and a Kanban board. It runs a daily press digest.
- **oh-my-pi** (`omp`): a terminal coding agent with separate models for planning, quick edits and deep reasoning, across many providers.
- **OMH, oh-my-hermes**: skills and roles for Hermes, under evaluation.

Models by role: Claude Fable 5.2 leads and orchestrates the agents, Claude Opus 5.5 writes code, DeepSeek V4.1 Flash (release 1017) serves API calls, GPT-6 Luna reads.

I apply mathematics to the problems I meet. Each solution leads to new problems, so I keep a solution as small as it can be. The reasoning is in [philosophy](https://github.com/maciejszulia/philosophy). Why a request to a machine is dangerous: [notes/why-ai-is-dangerous.md](notes/why-ai-is-dangerous.md).
